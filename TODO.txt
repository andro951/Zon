Script execution time issue:
  -It was taking a long script 40-50ms to run (3-4 frames).
  -Made improvements to GrammarForge's execution time, but not good enough ~30ms to run.
  -The problem was mainly console.log() takes ~0.5ms each time it's called. Without them, it runs in ~0.4ms instead of ~30ms.

Automatic conversion between Number (JS double) and BigNumber (my custom floating point type bigger than double)
  -The player and/or script writer doesn't know that BigNumber exists.  All they see is numbers as text.
    They don't interact with conversions at all.
  -Replaced all opperator functions in GrammarForge, +, -, /, *, ^, -#, +#, ==, !=, >, <, >=, <=, %
  -Operators check if one is a BigNumber, if so, it promotes the other to BigNumber and uses the BigNumber operator.
    If both are doubles, it checks if the result will overflow and instead converts to BigNumber.  
    If no overflow, do the Number operation.
    When returning a BigNumber value, it always tryes to convert it to a Number by checking if it is smaller than Number.MAX_VALUE.
